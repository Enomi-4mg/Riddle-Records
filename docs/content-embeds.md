# 本文のリンク・埋め込み

CMSの空の段落にURLを貼り付けると、通常リンク・リンクカード・対応サービスの埋め込みを選べます。
＋またはスラッシュメニューの「リンク・埋め込み」からも挿入できます。
選択した文字へのリンク貼り付けや、複数行の貼り付けは通常の編集操作です。

リンクカードは、noteのようにタイトル・説明・画像・サイト名をまとめて表示します。
サイト内の記事は選択欄から選ぶか、`/journal/…/` などのURLを入力します。
Journal、Galleryの詳細ページ、楽曲、Projectsが対象です。
公開ページではビルド時に参照記事の最新情報を使います。
削除された記事や非公開の記事は元URLの通常リンクとして表示し、保存済みのタイトルや画像は公開しません。

外部カードのタイトル・説明・画像はURLから自動取得できます。
取得後は各項目を修正でき、「情報を再取得」で更新できます。
既存カードを編集するときは保存済みの情報を保持します。
取得に失敗しても手動入力できます。
外部カード情報は本文へ保存され、ページ閲覧時に再取得しません。

YouTubeの動画URL、Xの投稿URL、Spotifyの曲・アルバム・プレイリスト等のURLから専用埋め込みを作れます。
動画・音楽の自動再生は行いません。
サービス側で表示できない場合も元リンクを残します。
ブロックの「編集」でURL・表示方法を変更でき、「通常リンクにする」で解除できます。
既存のiframeなどのHTMLはHTML互換ブロックとして保持し、一括変換しません。

## Markdownでの保存

通常リンクは `[表示する文字](https://example.com)` です。
専用ブロックは以下の形式で本文に保存します。

````markdown
```riddle-embed
{
  "kind": "card",
  "url": "/journal/2026-08-02/"
}
```
````

`kind` は `card`・`youtube`・`x`・`spotify`。
`url` は必須で、カードには任意の `title`・`description`・`image` を指定できます。
内部カードの表示情報は参照記事から取得します。
不正な種類・URL・JSONはコードブロックのまま保持します。

## メタデータAPI

CMSの `POST /api/link-metadata` に `{ "url": "https://…" }` を送ると、`title`・`description`・`image` の文字列を返します。
OG情報を優先し、ページタイトルとdescriptionを補完に使います。
エラーは400と `{ "error": "…" }`。取得失敗は記事の保存を妨げません。

本番Workerは既存のCloudflare Access保護下で提供し、ローカル開発APIも同じ応答形式を使います。
公開HTTPSページのみを取得し、DNSの公開アドレス検証をリダイレクト先にも適用します。
ローカル取得では検証したIPへ接続先を固定します。
取得は8秒、HTMLは1 MiB、リダイレクトは3回までです。
CMSやGitHubの認証情報をリンク先に送らず、取得HTMLのscriptを実行しません。
