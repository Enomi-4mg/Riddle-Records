# Content Editor の UX ユースケース

この文書は、Riddle Records Content Editor のレビュー項目をまとめた作業用チェックリストです。
Journal、Songs、Gallery、Projects の編集が安全で予測しやすく、実用的に行えるかを確認します。

## 基本的な編集

- 既存の Markdown ファイルを開き、内容を変更せずに閉じる。未保存のバックアップが誤って作成されず、次回起動時に復元を求められないこと。
- 既存の Markdown ファイルを開き、本文を少し編集して、ファイルへ保存せずに閉じる。その際に警告が表示され、再度開いたときにローカルの未保存バックアップを復元できること。
- タイトル、日付、slug、タグ、下書き状態など、frontmatter だけを編集する。本文の編集時と同じ未保存変更の処理が適用されること。
- 新しい項目を作成し、必須項目を入力して、選択したコンテンツ種別に対応するディレクトリへ保存できること。
- 単独の Markdown ファイルを読み込んで保存する。ファイル名が有効なら再利用し、無効なら frontmatter からファイル名を生成すること。

## 保存と競合への対策

- 読み込んだファイルを保存し、編集を続けて再度保存する。2回目の保存では最新の更新時刻を使い、誤った競合を報告しないこと。
- 別のプロセスが同じファイルを変更した後に保存する。競合通知から再読み込みまたは上書きを明確に選べること。
- Journal または Songs の日付、Gallery または Projects の slug など、ファイル名の生成に必要な項目がない状態で保存する。どの項目が保存を妨げているか通知すること。
- 設定画面の「下書きのまま保存」を使う。`draft: true` を設定してファイルを保存すること。
- 上部バーの「Markdown保存」を使う。下書き状態を暗黙に変更せず、現在の Markdown を保存すること。

## コンテンツ種別ごとの確認

- Journal：種別を `journal`、`making`、`report` の間で切り替え、URL とファイル名の規則を確認する。
- Journal：サムネイルを追加し、`thumbnail_alt` がない場合に警告されることを確認する。
- Songs：`youtube_id`、クレジット、歌詞の複数行テキストが保たれることを確認する。
- Gallery：`image`、`thumbnail`、`thumbnail_alt`、`detail`、タグ、記事リンクが標準の Gallery frontmatter を保ったまま入出力されることを確認する。
- Projects：Markdown 本文、メイン画像、機能一覧、リンク、タグ、状態が全画面プレビューにすべて反映されることを確認する。

## チェックとプレビュー

- 長い記事を書きながらサイドプレビューを開く。プレビューのスクロール位置がエディタのスクロールにおおむね追従すること。
- サイドレールと「その他」メニューのどちらからでも、チェック画面と出力画面を開けること。
- 各コンテンツ種別の全画面プレビューを開き、公開される Astro ページの表示意図と比較する。
- Markdown 全体、frontmatter、本文をコピーする。クリップボードの権限エラーが発生した場合、対処可能な通知を表示すること。

## 小さい画面とキーボード操作

- モバイル幅で、上部バー、競合通知、削除確認、設定ボタン、ファイル行が重ならずに折り返されること。
- タブレットまたはモバイル幅でサイドレールを使わずに操作する。確認に必要な操作がすべて「その他」メニューから行えること。
- ファイルに未保存の変更がある状態で、ブラウザのタブを再読み込みまたは閉じる。変更が失われる前にブラウザが警告すること。

## 破壊的な操作

- 既存ファイルを削除し、確認画面にコンテンツ種別、パス、タイトルが表示されること。
- 未保存の新しい Markdown 項目を閉じる。実在するファイルの削除ではなく、未保存項目を閉じる操作として説明されること。
- 削除確認を取り消し、ローカルの変更を失わずに編集を続けられること。
